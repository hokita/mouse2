# Game Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a game-selection menu as the app's entry point, so the existing dodger becomes one selectable game instead of the thing that auto-starts.

**Architecture:** A new `MenuScene` (Phaser Scene, key `'MenuScene'`) becomes the first scene in `main.ts`'s scene list, rendering one tappable button per entry in a new static registry (`src/games.ts`). Tapping a button calls `this.scene.start(sceneKey)`. `GameScene`'s Game Over screen gets a matching `"Back to Menu"` button (alongside the existing restart), which requires fixing `GameScene` to fully reset its state on every scene entry, not just on manual in-place restart.

**Tech Stack:** Phaser 3 (scenes, GameObjects, input), TypeScript (strict mode), Vite, Vitest (existing `src/core/*` suite only — unaffected by this plan).

## Global Constraints

- Target viewport: portrait, `WIDTH = 430` / `HEIGHT = 932` (`src/gameConfig.ts`) — don't hardcode other dimensions.
- Visual style: flat-colored `Phaser.GameObjects.Rectangle` + plain `Text`, no sprites/images/icons — matches the existing dodger's placeholder look.
- Touch/tap only — no keyboard navigation, no animations/transitions between scenes.
- TypeScript `strict: true` with `noUnusedLocals`/`noUnusedParameters` (`tsconfig.json`) — remove code you make dead, don't leave it unreferenced.
- **Testing convention for this plan:** `src/core/*` (score/spawner/collision) is the only unit-tested layer in this codebase (Vitest, red/green TDD already satisfied by existing tests) — this plan does not touch it. `src/scenes/*` (`MenuScene.ts`, `GameScene.ts`) is plain Phaser glue with no non-trivial pure logic, verified manually via `pnpm dev` instead of unit tests — this is the established convention for this codebase (see `docs/superpowers/specs/2026-08-10-portrait-dodger-design.md` and `docs/superpowers/specs/2026-08-11-game-menu-design.md`), not a deviation invented for this plan.
- No high-score persistence, no second real game — `src/games.ts` lists only the dodger.

- [ ] **Step 2: Create MenuScene**

Create `src/scenes/MenuScene.ts`:

```ts
import Phaser from 'phaser';
import { WIDTH, HEIGHT } from '../gameConfig';
import { GAMES } from '../games';

const TITLE_Y = HEIGHT * 0.25;
const BUTTON_WIDTH = 260;
const BUTTON_HEIGHT = 70;
const BUTTON_SPACING = 24;
const FIRST_BUTTON_Y = HEIGHT * 0.45;
const BUTTON_COLOR = 0x4444ff;

export class MenuScene extends Phaser.Scene {
  constructor() {
    super('MenuScene');
  }

  create(): void {
    this.add
      .text(WIDTH / 2, TITLE_Y, 'mouse2', {
        fontSize: '40px',
        color: '#000000',
      })
      .setOrigin(0.5, 0.5);

    GAMES.forEach((game, index) => {
      const y = FIRST_BUTTON_Y + index * (BUTTON_HEIGHT + BUTTON_SPACING);

      const button = this.add.rectangle(WIDTH / 2, y, BUTTON_WIDTH, BUTTON_HEIGHT, BUTTON_COLOR);
      button.setInteractive({ useHandCursor: true });
      button.on('pointerdown', () => this.scene.start(game.sceneKey));

      this.add
        .text(WIDTH / 2, y, game.title, {
          fontSize: '24px',
          color: '#ffffff',
        })
        .setOrigin(0.5, 0.5);
    });
  }
}
```

## Task 2: Fix GameScene to fully reset state on every scene entry

**Files:**
- Modify: `src/scenes/GameScene.ts:31-39` (field declarations)
- Modify: `src/scenes/GameScene.ts:45-65` (`create()`)
- Modify: `src/scenes/GameScene.ts:218-230` (`restart()`)

**Interfaces:**
- Consumes: nothing new from Task 1 — this is an internal refactor of `GameScene`, independently reviewable and testable via the existing single-entry flow (`pnpm dev` still starts straight into `GameScene` today only if you tap the menu button; behavior inside the game is unchanged by this task).
- Produces: `private resetState(): void` on `GameScene`, called from both `create()` and `restart()`. Task 3 will call it directly from a new restart button and delete the now-redundant `restart()` wrapper.

**Why:** `create()` currently only runs once per page load, so `scoreState`, `spawnerState`, `obstacles`, and `prevPlayerX` are initialized only via field initializers (run once, at construction) or the manual `restart()` method. Once Task 1's menu can route into `GameScene` repeatedly, Phaser reuses the same `GameScene` instance and re-runs `create()` on every `scene.start('GameScene')` — without this fix, a second visit would start with stale score/obstacles from the previous round.
